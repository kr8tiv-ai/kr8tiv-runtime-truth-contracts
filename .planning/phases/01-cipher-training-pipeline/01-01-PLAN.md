Build the complete training data curation pipeline for Cipher Code Kraken. This produces all 4 datasets (SFT, SimPO, GRPO, KTO) from scraped creative code sources (GitHub repos, CodePen pens). Purpose: Training data quality is the single biggest factor in model quality. This plan creates the tooling to collect, filter, format, and structure all training data before any model training begins.
Output: 4 JSONL dataset files ready for training, plus reusable scraping/formatting/scoring scripts.
</objective>

  <action>
Create 3 Python scripts and 1 orchestration notebook.

**scripts/slop_detector.py:**
- Function `slop_score(code: str) -> dict` returning `{"score": float, "signals": list[str], "is_slop": bool}`
- Negative signals (each adds to slop score):
  - Div soup: >70% of HTML elements are `<div>` (+3.0)
  - Gradient hero: patterns `bg-gradient-to`, `from-purple`, `to-blue` (+2.0 each match)
  - Template naming: `hero-section`, `cta-button`, `feature-card` (+2.0 each)
  - Generic copy: `Welcome to`, `Get Started`, `Learn More`, `Lorem ipsum` (+2.0 each)
  - Missing interactivity: no `addEventListener`, no `gsap`, no `THREE`, no `Lenis`, no `requestAnimationFrame` (+3.0)
  - Utility-class-only: no custom CSS (`@keyframes`, `clip-path`, `mix-blend-mode`, `transform:`, custom properties `--`) (+2.0)
  - No canvas/WebGL/SVG: none of `<canvas`, `<svg`, `WebGL`, `gl_` (+2.0)
  - `animate-bounce` or `animate-pulse` (+2.0 each)
- Positive signals (each subtracts from slop score):
  - `THREE.` or `three` import (-2.0)
  - `gsap.` or `ScrollTrigger` (-2.0)
  - `Lenis` or `lenis` (-1.5)
  - `requestAnimationFrame` (-1.0)
  - `gl_FragColor` or `shader` (-2.0)
  - `clip-path` or `mix-blend-mode` (-1.5)
  - `IntersectionObserver` (-1.0)
  - `canvas` usage (-1.0)
  - Code length > 50 lines (-1.0), > 150 lines (-1.0 additional)
- `is_slop = True` if score > 5.0
- Also export `creative_code_reward(completions: list[str]) -> list[float]` that returns reward scores (negated slop_score logic, matching the GRPO reward function pattern from research). This exact function will be used in GRPO training.

**scripts/data_formatter.py:**
- Function `format_sft(raw_entry: dict) -> dict` that takes a scraped entry and produces chat-template format:
  ```json
  {"conversations": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
  ```
- The "user" content is a synthetic instruction generated from analyzing the code: detect what libraries are used (Three.js, GSAP, Lenis, etc.), what technique is demonstrated (particle system, scroll animation, shader, etc.), and compose a natural instruction like "Create a Three.js particle system that responds to mouse movement with GSAP-powered easing transitions"
- The "assistant" content is the full source code wrapped in a markdown code fence, followed by a brief explanation of key techniques
- Function `format_simpo(chosen_entry: dict, rejected_code: str) -> dict` producing `{"prompt": "...", "chosen": "...", "rejected": "..."}`
- Function `format_grpo(entry: dict) -> dict` producing `{"prompt": "..."}` (prompt only, model generates responses)
- Function `format_kto(entry: dict, label: bool) -> dict` producing `{"prompt": "...", "completion": "...", "label": true/false}`
- Accept `--input` (raw JSONL), `--output` (formatted JSONL), `--format` (sft|simpo|grpo|kto) CLI args
- Filter out entries where code is < 50 lines (too short for full component, per research anti-pattern)

**scripts/rejected_generator.py:**
- Function `generate_rejected(prompt: str, chosen_code: str) -> str`
- Takes a creative code prompt and its hand-crafted chosen answer, produces a "competent but generic" rejected version
- Strategy: strip creative techniques (Three.js, GSAP, shaders) and replace with Tailwind utility classes, basic CSS, div-based layout
- Replace `THREE.Scene/Mesh/BufferGeometry` with plain `<div>` elements
- Replace `gsap.to/from/fromTo` with CSS `transition` or `animate-*` Tailwind classes
- Replace `Lenis` smooth scroll with native `scroll-behavior: smooth`
- Replace `<canvas>` or `<svg>` with `<div>` + background gradient
- Keep the same general structure/sections so the contrast is in quality of technique, not completeness
- The rejected output must still be valid HTML/JS -- competent but generic, NOT broken
- Verify rejected output with `slop_detector.slop_score()` -- it MUST score > 5.0 (is_slop=True)

**notebooks/01_data_curation.ipynb:**
- Jupyter notebook that orchestrates the full pipeline
- Cell 1: Install deps (`!pip install PyGithub requests beautifulsoup4`)

- Cell 7: Generate GRPO prompt-only dataset from SFT prompts
- Cell 8: Generate KTO dataset: label=True for entries with slop_score < 2.0, label=False for entries with slop_score > 6.0
- Cell 9: Print dataset statistics (count, avg length, quality score distribution)
- Cell 10: Save all 4 datasets to data/prompts/*.jsonl
- All cells must be markdown-documented with rationale
- Target output sizes: SFT ~2000+, SimPO ~1000+, GRPO ~500+, KTO ~500+
